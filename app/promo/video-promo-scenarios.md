# 寻藏视频宣传文案：8 个补充场景

> 状态：草案
> 更新日期：2026-09-29
> 用途：后续独立短视频的痛点、配音和分镜素材
> 主片：[聊天图片找源文件 · 40 秒文案](video-promo-copy.md)

## 2. 场景 02：商品图换了背景，素材就找不到了

**用户痛点：**同事只有一张商品参考图，要求找到以前拍过、做过的素材。文件名可能只是编号，背景和角度又不一样，按名字很难找。

**开场对话：**“这款杯子以前拍过吧？把之前那组图找出来。”

**封面大字：**看着像同款，素材在哪？

**可直接配音：**

> 同事发来一张商品图：“这款以前拍过，找下旧素材。”可是文件名全是编号，背景和角度还不一样，一张张翻，很容易看漏。把参考图放进寻藏，选中商品主体，或者框出需要查找的区域，在已建立索引的素材里寻找外观相近的候选。打开结果，核对款式、细节和用途，再拿去做新的页面。找商品素材，从看得见的东西开始。

**分镜与大字：**

| 阶段 | 画面 | 大字 |
| --- | --- | --- |
| 收到需求 | 聊天中出现一张有复杂背景的杯子照片。 | 这款，之前拍过吗？ |
| 翻找困境 | 一组编号文件掠过，旁边叠出白底图、场景图、不同角度。 | 名字不记得，背景也变了。 |
| 功能操作 | 把参考图放入寻藏，选中商品主体或框选区域。 | 选中主体，查找相似。 |
| 结果核对 | 展示少量候选，打开一张核对杯口、把手与款式。 | 找到候选，再核对细节。 |
| 收尾 | 打开素材所在文件夹，回到页面制作。 | 旧素材，接着用。 |

**演示前准备：**主体检索需要相应特征与索引。自动检测、分割使用兼容模型；也可以演示矩形框选。口播保持“外观相近的候选”，不把视觉相似等同于同款鉴定。

## 3. 场景 03：客户要高清照片，却只发来一张小图

**用户痛点：**客户从聊天记录或样片中挑了一张照片，只记得画面。摄影师需要回到本地照片目录核对文件，而不是继续转发已经压缩的小图。

**开场对话：**“就这张，发我高清的。”

**封面大字：**客户说“就这张”，文件名呢？

**可直接配音：**

> 客户圈出一张照片：“就这张，发我高清的。”可小图上没有编号，拍摄又分了好几个目录。名字找不到，画面就是线索。把这张参考图放进寻藏，在已索引的本地照片里查找相似候选。打开结果，核对人物、构图和文件尺寸，再进入所在文件夹，取用原先保存的照片。把时间留给修图和交付，少花在反复对照片上。

**分镜与大字：**

| 阶段 | 画面 | 大字 |
| --- | --- | --- |
| 收到需求 | 聊天中客户发来小图，标注“这张”。 | 就这张，要高清。 |
| 翻找困境 | 多个拍摄日期目录与连续编号照片来回切换。 | 记得画面，不记得编号。 |
| 功能操作 | 粘贴或拖入参考图，查询本地照片索引。 | 用画面查照片。 |
| 结果核对 | 打开候选对比人物、构图与文件信息。 | 核对照片与尺寸。 |
| 收尾 | 点击所在文件夹，选中用于交付的图片。 | 找到文件，继续交付。 |

**演示前准备：**使用已验证可读取并参与索引的照片，例如 JPG。文案不预设 RAW 支持；演示的是定位本地已存在的照片，不是把聊天小图变高清或恢复已删除文件。

## 4. 场景 04：只有视频截图，不知道镜头在哪

**用户痛点：**对方发来一张截帧，要求使用那段镜头。视频文件很多，一条条打开、拖动时间线会打断剪辑思路。

**开场对话：**“上次这个镜头，再用一下。”

**封面大字：**记得这一帧，忘了是哪条片。

**可直接配音：**

> “上次这个镜头，再用一下。”对方发来一张截图，你却要打开一条又一条视频，拖着时间线找画面。先让寻藏为视频抽帧并建立索引，再用截图搜索相似画面。从结果打开视频，跳到命中位置，播放核对前后内容。需要的片段，设置入点和出点后再导出。让截图成为找镜头的线索，把注意力放回剪辑。

**分镜与大字：**

| 阶段 | 画面 | 大字 |
| --- | --- | --- |
| 收到需求 | 聊天里出现一张窗边喝咖啡的视频截图。 | 这个镜头，在哪条视频？ |
| 翻找困境 | 多个播放器窗口叠放，时间线反复左右拖动。 | 一条条打开，一段段翻。 |
| 功能操作 | 在已准备好的视频库中放入截图查询。 | 用截图，查视频画面。 |
| 结果核对 | 点击一条命中，播放器跳转到候选时间，播放前后数秒。 | 回到命中位置。 |
| 收尾 | 设置入点、出点，显示导出片段操作。 | 找到镜头，接着剪。 |

**演示前准备：**视频已完成扫描、抽帧和对应向量构建；FFmpeg 等相关运行工具就绪。结果是抽帧检索的命中位置，需要回放核对，不表示覆盖每一帧。导出采用已经核对的范围。

## 5. 场景 05：没图可搜，但记得大概长什么样

**用户痛点：**素材存在电脑里，却不记得文件名和路径，手头也没有参考图片。只能描述颜色、环境或画面主题。

**开场独白：**“我明明存过一张雨天街道，反光特别好看……”

**封面大字：**记得画面，说出来找。

**可直接配音：**

> 你记得存过一张雨天街道，路面有灯光倒影，可名字和路径都忘了，连参考图也没有。试着把记得的画面说清楚。相关模型与素材索引准备好后，在寻藏里输入“雨天街道，路面灯光倒影”，查找内容相关的候选。结果太宽，就补充描述，再打开图片核对。让记忆里的颜色、场景和主体，变成查找素材的线索。

**分镜与大字：**

| 阶段 | 画面 | 大字 |
| --- | --- | --- |
| 回忆画面 | 简单的雨滴、街道、倒影图形逐个出现。 | 记得长什么样。 |
| 翻找困境 | 文件搜索框输入模糊名字，结果与记忆不符。 | 却不记得叫什么。 |
| 功能操作 | 在语义查询框输入“雨天街道，路面灯光倒影”。 | 描述画面，查相关素材。 |
| 结果核对 | 一组候选出现，选择接近记忆的一张打开。 | 从候选里，找回那张图。 |
| 收尾 | 图片回到创作工作区旁边。 | 让画面成为线索。 |

**演示前准备：**配置兼容的文本编码模型及图片向量，中文查询使用对应多语言能力。只展示实测可复现的查询和结果；语义检索返回相关候选，不等于精准理解所有描述。

## 6. 场景 06：备份了很多次，重复文件也越攒越多

**用户痛点：**素材从下载、聊天、项目、备份中反复保存，文件名不同，字节内容却可能一样。哪些是真副本、哪些只是看起来像，靠缩略图不好分辨。

**开场独白：**“这张图，我到底存了多少份？”

**封面大字：**文件夹换了名字，内容还是那一份。

**可直接配音：**

> 下载存一份，聊天再存一份，项目备份又复制一份。目录越来越多，同一份文件到底占了多少地方？用寻藏的重复文件查找，扫描选定目录，查看内容完全一致的副本分组、数量和位置。如果只是画面相似、尺寸不同，再进入图片相似检索，逐张对比。先分清完全重复和视觉相似，再打开文件位置，决定哪些需要保留。

**分镜与大字：**

| 阶段 | 画面 | 大字 |
| --- | --- | --- |
| 素材积累 | 同一文件进入“下载”“项目”“旧备份”三个目录。 | 同一份，存了好多遍。 |
| 翻找困境 | 文件名各不相同，人物在两个缩略图间犹豫。 | 真重复，还是只是像？ |
| 功能操作 | 扫描选定范围，展示完全重复分组及位置。 | 先查内容一致的副本。 |
| 补充分支 | 画面相似但文件不同，转到图片相似检索对比。 | 相似图片，单独核对。 |
| 收尾 | 打开所在目录，停在人工核对画面。 | 先看清，再整理。 |

**演示前准备：**完全重复查找依据文件内容，相似图片检索依据图像特征。当前查重面板以分析、定位为主，分镜不添加不存在的“一键自动安全删除”按钮。

## 7. 场景 07：素材收藏了一堆，真正用时还是找不到

**用户痛点：**每次找参考都要重新翻目录。上次已经找到的海报、配色、商品图没有形成可复用的整理方式。

**开场独白：**“我上次找到的那组参考，又去哪了？”

**封面大字：**找到过，不等于下次找得到。

**可直接配音：**

> 好不容易找到一组参考，项目一结束，下次又得从头翻。找到素材以后，还可以多做一步。在寻藏素材库里，把常用内容加入收藏或集合，用分类和标签记录它的用途。比如“春季上新”“暖色包装”“客户确认参考”。下次接到相似需求，按标签筛选，再打开需要的素材。让这次的查找，成为下次能继续用的积累。

**分镜与大字：**

| 阶段 | 画面 | 大字 |
| --- | --- | --- |
| 收到新需求 | 聊天出现“沿用上次那组参考的方向”。 | 上次那组参考呢？ |
| 翻找困境 | 旧目录再次展开，已找过的素材又混进大量文件。 | 找到过，又得重新找。 |
| 功能操作 | 在素材库中选择已同步的素材，加入集合并添加用途标签。 | 按项目和用途整理。 |
| 再次使用 | 新项目出现，点击标签或集合筛选素材。 | 下次从整理结果开始。 |
| 收尾 | 打开其中一项，回到创作流程。 | 让找过的素材，继续有用。 |

**演示前准备：**素材已从图片索引同步到素材库。标签与集合用于整理记录，画面不把它表现为自动移动原始目录，也不暗示已提供多人实时协作。

## 8. 场景 08：硬盘快满了，却不知道空间去了哪里

**用户痛点：**导出视频或保存项目时才发现空间不足。素材、旧导出、安装包、缓存混在不同目录中，不敢随便删除。

**开场提示：**“磁盘空间不足，无法继续保存。”

**封面大字：**硬盘满了，到底谁占的？

**可直接配音：**

> 项目快做完了，电脑却提示磁盘空间不足。到底是素材太多、旧导出没清，还是备份占了地方？先用寻藏查看选定目录中的大文件和文件夹大小，把占用较大的项目找出来。点开所在位置，核对文件用途、日期和是否还需要保留，再决定怎么处理。空间整理，先从看清楚开始，不用凭感觉翻文件夹。

**分镜与大字：**

| 阶段 | 画面 | 大字 |
| --- | --- | --- |
| 遇到中断 | 保存或导出操作旁出现“空间不足”的情景提示。 | 偏偏在交付前，硬盘满了。 |
| 翻找困境 | “旧导出”“备份”“下载”“项目”目录轮番出现。 | 大文件，藏在哪一层？ |
| 功能操作 | 选择要分析的目录，展示大文件列表与大小。 | 先找占用大的文件。 |
| 结果核对 | 打开某个旧导出的所在目录，查看文件信息。 | 看清用途，再决定处理。 |
| 收尾 | 将候选清单和路径留在画面中，不演示自动删除。 | 空间占用，看得明白。 |

**演示前准备：**主镜头使用已经具备的最大文件分析、文件夹大小与定位操作。权限或路径不可访问时结果可能不完整，保留界面中的进度、下限或部分结果提示。不要把文件逻辑大小直接等同于必定可释放的磁盘空间。

## 9. 场景 09：新素材放进去了，为什么还搜不到

**用户痛点：**往素材目录放了新文件后就开始搜索，却不清楚数据源是否登记、索引是否更新、模型是否准备完成。搜索结果少时容易无从排查。

**开场独白：**“图片明明就在这个文件夹，怎么没搜到？”

**封面大字：**文件放进去了，为什么还搜不到？

**可直接配音：**

> 图片明明放进了文件夹，搜索里却还没出现。先看看寻藏准备到了哪一步：来源目录选对了吗？新增素材扫描了吗？对应模型和索引准备好了吗？从来源和准备状态开始，更新需要搜索的范围，等任务完成，再用参考图查询。图库不断增加，查找能力也需要维护。把建库、搜索和维护接起来，才知道现在能搜什么。

**分镜与大字：**

| 阶段 | 画面 | 大字 |
| --- | --- | --- |
| 产生困惑 | 新图片进入素材目录，旁边显示旧查询结果。 | 新文件，还没进入索引。 |
| 查看状态 | 展示来源、扫描、向量准备等状态，圈出实际未完成的一步。 | 看清准备到了哪一步。 |
| 功能操作 | 选择正确来源，更新扫描并按需补齐对应索引。 | 更新需要搜索的范围。 |
| 结果核对 | 任务完成后，用新图片查询并打开候选。 | 准备完成，再查找。 |
| 收尾 | 简洁流程图连接“添加来源 → 建立索引 → 搜索 → 更新维护”。 | 图库会增长，索引也要维护。 |

**演示前准备：**使用一个包含新增图片的测试目录，真实展示更新前后状态。这是由用户操作触发的准备和维护流程，不表现为始终实时同步。外接盘临时离线时展示来源不可用，不能画成素材已经删除。

## 10. 系列视频的统一表达

每条视频只讲一个问题，按“收到需求或遇到困难 → 原来的翻找方式 → 寻藏的一个具体操作 → 打开结果核对 → 回到工作”的顺序展开。

建议按这个顺序制作：聊天图片找源文件 → 截图找视频 → 文字描述找素材 → 主体找商品 → 重复与空间盘点 → 收藏整理 → 索引维护。摄影场景适合单独面向摄影与活动拍摄受众发布。

可轮换的片尾句：

- 寻藏，把翻找文件的时间，还给创作。
- 找到素材，继续做事。
- 记不住文件名，就从画面开始找。
- 让找过的素材，下次还找得到。

画面中的素材数量、文件大小和等待时间采用实际录制数据；示意动画单独标注“流程示意”。聊天、客户与素材名称使用示例内容。

功能条件集中放在录制准备和必要的小字说明中；口播优先讲具体动作及结果。核心检索依赖已经准备好的本地索引；模型由用户自行获取和配置。相似结果需要打开核对。
